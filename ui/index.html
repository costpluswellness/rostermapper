          How Roster Mapper works

          1 · Upload

          • Drop xlsx, xls or csv files, or a folder of them. They're read in this browser; SSNs are removed as they're read.
          • Every file is mapped, standardized and checked as the command line does, and Results shows what happened. Click a file to review it.
          • The header row is found automatically. To change it, open Raw data on a file and click another row.
          • The action (ADD, UPDATE or TERM) comes from an action column, then the sheet name, then the file name.

          Results

          • The same tables as the workbook the command line writes: each sheet's counts, the mapping (each column, its field and why), every issue, and every row left out and why.
          • Download a workbook per sheet (Summary, Mapping, Data, Issues and Left out tabs), or all of them in a zip with summary.xlsx.

          AI transform soon

          • Some rosters don't fit one row per provider and location. AI can detect and make these transformations. Example transformations:
            • Wide to long: several locations in one row become one row per location.
            • Extracting fields merged into another column, such as effective dates, addresses or names.
            • Inferring fields from the file's metadata or structure, such as license state, primary location or show_in_dir.

          Mapping

          • Find the header row: scan the first 30 rows and pick the one that looks most like labels, with data below it.
          • Normalize headers: lowercase them and remove underscores, so PROV_FIRST_NM → prov first nm, then apply any vocabulary transformations.
          • Detect value types: profile each column's values (digit checks and patterns) as NPI, TIN, date, phone, ZIP, state and so on.
          • Match to fields: compare each column's name with every field's aliases in schema/fields.yaml and give each field its best-scoring column. See the data dictionary.
          • Open Mapping on a file to click another column for a field, or set one value for every row. Save your choices as a mapping file for the next roster from this sender.

          Standardizing

          • Transform column values to standard formats:
            • Dates → YYYY-MM-DD
            • Tax IDs → XX-XXXXXXX
            • ZIP codes → 5 digits, restoring leading zeros Excel drops
            • Phones → XXX-XXX-XXXX
            • States → two-letter codes
            • Gender → M or F
            • Yes/No → 1/0 for is_pcp, is_primary_loc and show_in_dir
            • Provider types → SPEC, PCP, BH, APP… (see the data dictionary)
            • Actions → ADD, UPDATE or TERM only
            • Location types → Primary or Alternate
          • Values that can be told wrong on their own are flagged: an NPI that fails its check digit, a tax ID prefix the IRS doesn't assign, a taxonomy code not in the NUCC list.
          • Values that can't be cleaned are kept as written and flagged.
          • Click "edit" on an issue to type the right value for its rows.

          Checks

          • Compares the roster with outside sources, as turned on under New run: NPIs are looked up in NPPES and addresses in the Census geocoder. Run checks on a file looks them up again.
          • Census results are applied by default: city, state and ZIP, and a suite or building name moved to line 2. So are NPPES's legal name for a billing NPI and, when the roster has none, the provider's primary taxonomy. Open "changes from …" on a card to see them; "undo" puts yours back.
          • Other NPPES results are suggestions: accept one with "Use"; "undo" puts yours back.
          • A provider NPI that NPPES lists under someone else drops the row. When NPPES has the provider under another NPI, "Use" puts it in and keeps the row.

          Review

          • A file opens here, and everything about it happens here. At the top: its totals (sheets not ignored), Mapping, Raw data, Run checks and Download, then the open sheet's figures. Its sheets are tabs: click one to open it; × ignores one (a data dictionary, a notes tab), leaving it out of Results and the download; ↺ brings it back.
          • The graph shows which providers work at which locations and bill through which entities; the table lists each combination with its rows.
          • Each card carries the checks: values are taken as confirmed unless marked: ⚠ a suggestion ("Use" accepts it), ✕ a failure, green a value the roster didn't have, filled in from NPPES or Census (hover to see which). Click an NPI to open it in the NPPES NPI Registry.
          • Click a card to pin it and see its problems: "add" types a missing value, "edit address" opens every part of a practice or billing address to fix together (the new address is looked up again).
          • Issues show once per provider, location or billing entity (click its name to see its card), each with its fix: "mapping" opens the field in Mapping, "edit" types the right value, "Use" applies a source's value to every row of the entity, "Allow" keeps a sender's own code (such as AHP) as written, in this file and the next, until you remove it under Issues.
          • Download shows what the workbook will hold first: each sheet with its counts (untick one to leave it out) and the first rows. Confirm to save one workbook with every sheet kept: Summary, Mapping, Data, Issues and Left out.
