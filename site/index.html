        How Roster Mapper works

        1 · Upload

        • Drop an xlsx, xls or csv. It's read in this browser; SSNs are removed as it's read.
        • The header row is found automatically. Click another row in the preview to change it.
        • The action (ADD, UPDATE or TERM) comes from an action column, then the sheet name, then the file name.

        2 · AI transform soon

        • Some rosters don't fit one row per provider and location. AI can detect and make these transformations. Example transformations:
          • Wide to long: several locations in one row become one row per location.
          • Extracting fields merged into another column, such as effective dates, addresses or names.
          • Inferring fields from the file's metadata or structure, such as license state, primary location or show_in_dir.

        3 · Map

        • Find the header row: scan the first 30 rows and pick the one that looks most like labels, with data below it.
        • Normalize headers: lowercase them and remove underscores, so PROV_FIRST_NM → prov first nm, then apply any vocabulary transformations.
        • Detect value types: profile each column's values (digit checks and patterns) as NPI, TIN, date, phone, ZIP, state and so on.
        • Match to fields: compare each column's name with every field's aliases in schema/fields.yaml and give each field its best-scoring column. See the data dictionary.
        • Click another column to change a field, or set one value for every row. Save your choices as a mapping file for the next roster from this sender.

        4 · Standardize

        • Transform column values to standard formats:
          • Dates → YYYY-MM-DD
          • Tax IDs → XX-XXXXXXX
          • ZIP codes → 5 digits, restoring leading zeros Excel drops
          • Phones → XXX-XXX-XXXX
          • States → two-letter codes
          • Gender → M or F
          • Yes/No → 1/0 for is_pcp, is_primary_loc and show_in_dir
          • Provider types → SPEC, PCP, BH, APP… (see the data dictionary)
          • Actions → ADD, UPDATE or TERM only
          • Location types → Primary or Alternate
        • Values that can be told wrong on their own are flagged: an NPI that fails its check digit, a tax ID prefix the IRS doesn't assign, a taxonomy code not in the NUCC list.
        • Values that can't be cleaned are kept as written and flagged.
        • Hover a name, address or flagged value and click ✎ to fix it by hand.

        5 · Validate

        • Compares the roster with outside sources, as turned on under Upload: NPIs are looked up in NPPES and addresses in the Census geocoder.
        • Census results are applied by default: city, state and ZIP, and a suite moved from line 1 to line 2. Open "changes from Census" on a card to see them; "undo" puts yours back.
        • NPPES results are suggestions: accept one with "Use"; "undo" puts yours back.

        6 · Review

        • Visualize relationships by entity: which unique NPIs, tax IDs, billing entities and network records are being entered.
        • See which providers work at which locations and bill through which entities, and every issue by row.

        7 · Export

        • Download one record per row, with every field and its issues, as CSV or JSON.
